# 清洁机器人视觉系统：问题、可行性与需求

## 1. 要解决的问题

通过摄像头判断面前是否存在目标垃圾，并回答：**在哪里、是什么、各有多少个**。

目标为五类：**罐、瓶、包装物、杯、纸类物品**。当前画面中检测到任一目标，显示 `FAIL`；未检测到目标，显示 `PASS`。其他物体作为背景。

项目重点是视觉软件和便携摄像头装置，不要求机器人移动、导航或实际捡垃圾。

## 2. 可行性分析

**采用预训练模型和标准微调完成识别，使用电脑与摄像头搭建便携系统。**

| 方面 | 实现方案 |
|---|---|
| 软件 | 使用 Python：OpenCV 负责采集、预处理和显示，scikit-learn 实现传统分类方法，PyTorch 与 torchvision 实现 CNN 和目标检测。 |
| 硬件 | 使用电脑、真实摄像头或连接的手机摄像头，以及稳定支架；无需电机、底盘控制或嵌入式部署。 |
| 模型 | 使用适配五类垃圾的预训练模型，通过标准微调完成任务。 |
| 数据 | 选用 [TACO](TACO数据集.md)，统一映射为五类，按 70%／15%／15% 的目标比例划分训练、交叉验证和测试集；本地摄像头数据单独用于实际场景评估。 |
| 性能 | 小物体、遮挡、低照度和背景杂乱是重点风险；先跑通检测基线，再测漏检、误报和延迟，据此选择改进。 |

优先验证：**摄像头采集稳定性、五类垃圾识别效果，以及目标电脑上的处理延迟。**

## 3. 需求分析

### 3.1 系统功能

| 需求 | 完成标准 |
|---|---|
| 现场输入 | 连续或按需处理摄像头新采集画面；采集或处理失败时显示错误状态。 |
| 检测与分类 | 最终系统为每个可见目标输出边界框、五类之一的类别和得分；说明得分是否为概率。 |
| 当前画面计数 | 根据保留的检测结果，按独立物体实例统计五类数量，包含零计数。 |
| 图像判定与显示 | 显示画面、边界框、类别、物体得分、各类数量、`PASS/FAIL` 和响应时间。 |
| 模型切换 | 三种基线均能处理新画面；冻结参考系统和最终改进系统可直接选择，无需改代码。 |
| 实体装置 | 摄像头采用较低视角，固定设备与线缆；至少支持一种可重复的位置或角度调整，以及受控光照变化。 |

### 3.2 模型与改进

阶段 2 实现**三种实质不同的成熟方法**，至少一种具备检测、五类分类和计数能力。

模型组合示例：
- 手工特征 + MLP：输出图像级 `PASS/FAIL`。
- 冻结的预训练 CNN 特征 + 线性分类器：输出图像级 `PASS/FAIL`。
- 适配五类垃圾的目标检测器：输出框、类别、得分、计数及图像判定。

阶段 3 以物体级基线为主要参考，针对实测弱点提出假设，结合至少一篇相关研究实施改进。**先记录计划，再实施；冻结原版，保留实验结果。**

### 3.3 数据与验证

- **标注：** 明确五类边界、遮挡与忽略规则；TACO 真值仅由官方标注和固定类别规则转换，计数从有效实例推导，无法确定类别或完整数量的图片留出。TACO 的 PASS 仅表示官方标注经映射后无目标，未额外核验全图；本地空场景仍需人工核验。
- **划分：** TACO 按 70%／15%／15% 的目标比例划分训练、交叉验证和测试集，按场景组分配。同一布置的相邻帧、重复视图和光照变体放入同一分区。阶段 2 本地留出评估以至少 30 个独立场景为起始目标，包含至少 15 个 `PASS` 和 15 个人工核验的 `FAIL` 场景。
- **公平比较：** 三种基线使用相同图像级测试集。改进比较使用此前未参与开发或调参的同一测试集，覆盖五类、正常条件及至少两种困难条件；参数和阈值只在训练／验证集选择。
- **效果：** 报告图像级混淆矩阵、精确率、召回率和 F1；物体级按同类、IoU ≥ 0.50 一对一匹配，报告各类精确率和召回率；计数报告各类平均绝对误差及五类计数全部正确的图像比例，同时报告样本量。
- **速度：** 每个比较系统至少测 20 个新采集帧，计入预处理、推理、后处理和显示更新调用，报告延迟中位数与第 95 百分位数。

### 3.4 交付与复现

提供统一批量入口，模型 ID 使用 `baseline1`、`baseline2`、`baseline3`、`final`：

```bash
python predict.py --input_dir TEST_FOLDER --model MODEL_ID --output_dir RESULTS
```

物体级基线和最终系统输出 `images.csv`、`objects.csv`、`counts.csv`、`run_config.json`；仅图像级的基线输出图像结果与运行配置。失败输入保留失败状态。

提交代码、环境依赖、冻结模型与配置、类别映射、标注与数据划分、原始预测、评估脚本，以及报告和演示材料；在干净环境验证运行命令。
