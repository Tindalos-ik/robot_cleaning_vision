# TACO 数据集

本项目选用 **TACO（Trash Annotations in Context）作为公共数据来源**。训练与调参使用 TACO 的固定划分，三种视觉方法共用；本地摄像头数据用于实际场景评估和演示。

## 1. 数据内容

TACO 收集真实环境中的垃圾图像，包括道路、沙滩、树林等场景。一张图像可以包含多个物体，背景、光照、物体大小和遮挡情况各不相同。

它提供逐物体的类别与实例分割标注，采用 COCO 格式，能够支持目标检测、分类和计数。相比白底单物体分类数据，这类多物体场景更符合本项目的检测任务。

本项目使用官方 `annotations.json`，本地保存为 `data/raw/taco/annotations.json`。`annotations_unofficial.json` 是尚未经作者审核的社区提交标注，与当前数据分开。

### 数据规模

根据[官方标注文件](https://raw.githubusercontent.com/pedropro/TACO/master/data/annotations.json)统计：

| 项目 | 数量 |
|---|---:|
| 图像 | 1,500 张 |
| 已标注物体实例 | 4,784 个 |
| 原始细分类别 | 60 类 |
| 上级大类 | 28 类 |
| [官方数据压缩包](https://zenodo.org/records/3587843) | 约 2.7 GB |
| 本地原图总大小 | 约 4.75 GB（4.42 GiB） |

TACO 属于小规模视觉数据集，本项目采用预训练模型微调。五类映射后，分别统计各类保留的实例数，作为训练与评估的样本量依据。


## 2. 标注如何表示

COCO 标注将图像信息、类别目录和物体标注保存在同一个 JSON 文件中：

| 内容 | 主要字段 | 含义 |
|---|---|---|
| 图像 | `id`、`file_name`、`width`、`height` | 图像标识、路径和原始尺寸 |
| 类别 | `id`、`name` | 原始类别编号与名称 |
| 物体 | `image_id`、`category_id`、`bbox`、`segmentation` | 所属图像、类别、边界框和分割区域 |

`bbox` 使用 `[x, y, width, height]`：左上角坐标加框的宽、高。转换为项目要求的两个角坐标时：

- `xmin = x`，`ymin = y`
- `xmax = x + width`，`ymax = y + height`

坐标均基于原始图像，以左上角为原点。每个物体单独标注，因此可以直接按类别统计实例数量。

## 3. 映射为项目五类

TACO 的类别比项目更细，需要归并为固定的五类。下表列出典型对应关系：

| 项目 ID | 项目类别 | TACO 原始类别示例 |
|---|---|---|
| 1 | 罐 | `Drink can`、`Food Can` |
| 2 | 瓶 | `Clear plastic bottle`、`Other plastic bottle`、`Glass bottle` |
| 3 | 包装物 | `Crisp packet`、`Other plastic wrapper`、`Plastic film`、`Bread bag`、`Cereal bag`、`Retort pouch` |
| 4 | 杯 | `Paper cup`、`Disposable plastic cup`、`Foam cup` |
| 5 | 纸类物品 | `Normal paper`、`Magazine paper`、`Tissues`，以及符合项目定义的纸板片 |

映射依据是物体形态，而不是仅看材质：柔性包装袋归包装物，纸张、纸巾和纸板片归纸类；杯类限定为一次性杯。`Glass cup`、`Other plastic cup` 等标签需要结合图像确认是否属于该范围。脱离的瓶盖、拉环等范围外物体作为背景。

训练前保存完整映射表，记录原始类别 ID、名称与项目类别 ID，供三种方法共用。

## 4. 三种方法如何共用数据

同一张带物体标注的图片，可以生成三种方法所需的训练信息：

| 方法 | 从数据中使用什么 |
|---|---|
| 手工特征 + MLP | 从整张图像提取手工特征，使用图像级 `PASS/FAIL` 标签训练 |
| 冻结 CNN + 线性分类器 | 从整张图像提取 CNN 特征，使用相同图像级标签训练 |
| 目标检测器 | 使用每个目标的五类标签与边界框训练 |

图像级真值与计数统一从人工核验后的物体标注生成：

- 至少有一个未被忽略的五类目标：`FAIL`。
- 经人工确认没有五类目标：`PASS`，五类计数均为零。
- 每类计数：该类未被忽略的物体实例数量。
- 目标存在或数量无法判定的图像：单独标记。

这样可以在同一批测试图像上比较三种方法的图像判定，并额外评估检测器的定位、分类和计数。

## 5. 训练集、交叉验证集与测试集

采用一次固定划分。这里的“交叉验证集”指验证集（validation set），用于模型选择，不采用 K 折交叉验证。

| 数据分区 | 目标比例 | 用途 |
|---|---|---|
| 训练集 `train` | 70% | 学习模型参数；计算手工特征标准化所需的统计量 |
| 交叉验证集 `val` | 15% | 选择模型设置、判定阈值和检测后处理参数 |
| 测试集 `test` | 15% | 设置冻结后评估模型，报告最终指标 |

### 划分规则

- 先完成五类映射与标注核验，再按场景组分配图像。
- 同一场景的重复视图、裁剪及增强版本放入同一分区，增强只在分区确定后进行。
- 固定随机种子为 `42`，尽量保持各分区的五类覆盖与 `PASS/FAIL` 分布；比例按场景组约束调整。
- 保存各分区的图像 ID 和场景组 ID。三种基线使用相同清单，分别报告图像数、场景数和各类物体实例数。

训练集负责学习，交叉验证集负责选择，测试集负责评价。特征标准化参数在训练集拟合后，原样用于验证与测试。

### 本地数据的用途

本地采集用于评估实际装置的视角、地面背景和光照条件，与 TACO 测试结果分开报告。当前训练方案不要求使用本地数据训练模型。

阶段 2 本地留出评估以 30 个独立场景为起始目标，包括至少 15 个 `PASS` 和 15 个人工核验的 `FAIL` 场景。若阶段 2 测试结果被用于设计改进，阶段 3 最终比较使用新的独立测试场景。

## 6. 本地数据与读取

原图与标注已下载到 `data/raw/taco/`，保持官方文件名和目录关系：

```text
data/raw/taco/
├── annotations.json
├── batch_1/
├── ...
└── batch_15/
```

图片来自官方标注中 `flickr_url` 指定的原图链接，按 `file_name` 保存；上表分别列出了归档包与本地原图的大小。

全部图片已通过解码检查，标注中的图片与类别引用、图片尺寸均已核对。下载压缩包和临时文件已删除。原始数据目录已加入 `.gitignore`。

读取图片时应用 EXIF 方向信息；本次有 152 张图片在方向转换后才与标注宽高一致。使用 Pillow 时可通过 `ImageOps.exif_transpose` 完成转换，再进行后续缩放和特征提取。

五类映射及训练、验证、测试清单在数据处理阶段生成，原始图片和标注保留。
